# SIDE / SKY

非対称協力型 2D 横スクロールアクション。
一人は**ランナー**として走り、もう一人は**ガーディアン**として世界を書き換える。

> 「足場を置いて！」「今飛ぶ！」「敵は任せろ！」
> — 企画書 10 章

**まず読むなら [`docs/status.md`](docs/status.md)。** 出来ていること、直した実機バグと
その実測値、そしていま分かっている限界を一枚にまとめてあります。

企画書『SIDE / SKY（仮）』の **P1 段階（灰箱プロトタイプ）** を実装したもの。
1 ステージ通しで遊べる。ガーディアンの道具は 4 つ＋足場タップ発射、敵 3 種、
ギミック 14、チェックポイント 5。オンライン対戦と Android / iOS のビルドも通っている。

- **エンジン**: Godot 4.4（GDScript）
- **ターゲット**: iOS / Android ネイティブ
- **プレイ形態**: 1 台を二人で共有、または合言葉で 2 台（どちらも横持ち）
- **アート**: モックアップ3枚から切り出した**実画像素材**。写っていない敵とギミックは
  切り出した部品から合成（`assets/SOURCES.md` に出典、`docs/design-decisions.md` に理由）

## 遊び方

### モバイル（1 台を二人で共有・横持ち）

| 担当 | 画面 | 操作 |
|---|---|---|
| P1 ランナー | 左端 30% | 円形スティック（左右）＋ **JUMP** ＋ **SPRINT**。FPS のパッドと同じ並び |
| P2 ガーディアン | 残り 70% | ドラッグで照準、右下の 3 ボタンで能力切替、右端の弾ボタンで実行 |

スティックは**位置指定式**。中央より左を押せば即座に左（バック）、押しっぱなしで
走り続ける。**SPRINT は押しっぱなしで継続**——時間制限もクールダウンも無い。
空中では同じボタンが 1 回だけのエアダッシュになる。

**走りながらジャンプする方法が 2 つある。** 親指が 2 本あるなら
スティックを倒したまま JUMP を押すのが速い。片手しか空いていないなら、
**スティックをそのまま上へ弾く**（リング上部の青い弧を越える）とジャンプする。
横の入力は保持されたままなので、走りが途切れない。
弧を越えている間は「ジャンプ押しっぱなし」と同じ扱いで、深く倒すほど高く飛ぶ。

### デスクトップ（エディタ上での検証用）

| | |
|---|---|
| ランナー | `A` / `D`（または矢印）で移動、`Space` / `W` でジャンプ、`Shift` / `L` で**スプリント（押しっぱなし）** |
| ガーディアン | マウス移動で照準、**左クリック**で実行、`1` `2` `3` で能力切替、`Q` / `E` で倍率 |
| 共通 | `R` リスタート、`Tab` 役割交換、`C` で 3→2→1 カウント |

土管と?/レンガブロックは**固体**（ジャンプで越える／下をくぐる）。柵・木・花は装飾で当たり判定なし。

ジャンプは**可変ジャンプ**（長く押すほど高く飛ぶ）。ただし押し始めの
**0.15 秒は切られない**。ここが無かった頃はタッチの短い押下が毎フレーム減速を
掛けられて **39px** しか上がらず、身長 46px のランナーが自分より低くしか
飛べなかった。今は同じ 50ms のタップで **96px**、押しっぱなしで **133px**
（横の到達距離 193px）。落下側の重力は上昇側より重い（1500 → 2100）ので、
浮遊感が無く、着地点が読める。数値は `tools/verify.sh` が毎回実測して印字する。

コヨーテタイム 0.10 秒と先行入力 0.12 秒が入っているので、少し早い／遅い入力でも
成立する。ガーディアンが同じ瞬間に足場を合わせにくるので、ここは特に効く。

## ガーディアンの 3 能力

サポートゲージは最大 100、毎秒 +8 の共通リソース。

| | コスト | 制約 |
|---|---|---|
| **足場** (1) | 30 | 最大 2 枚・5 秒で消滅。3 枚目を置くと最古が消える |
| **壁** (2) | 25 | 最大 1 枚・4 秒。弾とレーザーを遮断する |
| **狙撃** (3) | 20 | 連射不可（0.6 秒）。**スコープ中は建築不可** |

最後の一行が設計の要。企画書 9 章の「神側が強すぎるとランナーが駒になる」を
潰すための制約で、`test/run_tests.gd` の `_test_scope_blocks_building` が
これを回帰テストとして固定している。

### スコープは「部分スコープ」

添付モックアップ 3 は全画面スコープだが、1 画面共有ではランナーの視界を奪ってしまう。
そこで**拡大はリング内だけ**にし、外側は減光のみ（`SCOPE_DIM_MAX_ALPHA = 0.35` が上限）。
レティクル・目盛り・倍率表示・弾数はモックアップ通りリング内に再現している。

## ステージ 1-1「Greenfield Plains」

企画書 5 章の 1-1〜1-4 の学習曲線を、1 本のステージに **6 区間・全長 18,300px**
として展開した。地形 24 枚、敵 20 体、ギミック 15 個、トゲ 11 本、チェックポイント 5 つ。

| 区間 | 教えること | 主な状況 |
|---|---|---|
| A | 足場 | 140px の助走ハンプ → 60px の段差 → **600px の穴**（ジャンプの到達距離 193px では絶対に届かない）＋ 歩行敵 2 体 |
| B | 狙撃 | 620px の隙間を渡す移動床、その上空に砲台。飛行敵、登りながら 2 体目の砲台 |
| C | 壁 | 3 連バースト砲台が真横から撃つ中、**幅 160px の足場が 3 枚**。横断するレーザーは壁で止めるかダッシュで抜ける |
| D | 崩落と扉 | 崩落床 3 枚で 580px を渡り、レーザー、スイッチ狙撃で 6 秒だけ開く扉 |
| E | 登り | 200px＋80px 上り → 200px＋140px 上り（足場が要る）→ リフト。上空から飛行敵 2 体 |
| F | 総合 | 両側から砲台、崩落床で 600px、最後にスイッチ扉、そして 540px の最終ジャンプ |

**ガーディアンの手が要る穴は 7 箇所**（x = 1900 / 3700 / 8900 / 11100 / 11700 /
13800 / 15100）。これは目視ではなく `test/run_tests.gd` の到達性監査が
毎回計算していて、ランナーの最大跳躍（登り量で目減りする実効幅）で届かない穴を
列挙する。届いてしまう穴が増えたら「ガーディアンが要らない場所」が増えた合図。

同じくペーシング監査が「ガーディアンが何もすることのない時間」を測っていて、
現在の最長無音は **4.4 秒**（区間再構成前は 7.6 秒）。企画書 8 章の
「神側を退屈させない」を目視ではなく数字で守っている。

各区間の間にチェックポイント（5 つ）。死んだら **0.45 秒**で直前のチェックポイントに戻る。

## 動かす

```bash
godot --path .              # プレイ
godot --editor --path .     # エディタで開く
```

初回起動時に Godot が `.godot/` を生成する（`class_name` の解決に必要）。

### 検証

```bash
tools/verify.sh /path/to/godot            # 全チェック
tools/verify.sh /path/to/godot --shots    # ＋スクリーンショット出力（要 xvfb）
```

4 段階を通す。

1. **インポート** — `class_name` グローバルが登録されるか
2. **パース** — `src/` と `test/` の全 `.gd` / `.gdshader` を読み込み、1 つでも壊れていたら落とす
3. **ロジックテスト** — 108 チェック（下記）
4. **起動** — 実際のステージを 240 フレーム走らせ、`SCRIPT ERROR` が出ないか

ロジックテスト（`test/run_tests.tscn`、108チェック）が見ているもの:

- ゲージの回復レート・消費・不足時に**何も生成されない**こと
- 足場 2 枚上限と最古の入れ替え、寿命の消化
- 壁 1 枚上限、壁が弾を食い止めてカウントされること
- **スコープ中は建築が拒否される**（企画書 4 章の中核制約）
- 狙撃のクールダウン、ゲージ由来の弾数表示、レティクル下の敵が死ぬこと
- ジャンプ到達高・到達距離が設計帯（105〜140px / 175〜250px）に入っていること、
  およびタップジャンプが身長を超えること
- ダッシュ距離と「空中 1 回だけ」
- 歩行敵に上から乗っても倒せず、ランナーが被弾すること。飛行敵も踏めない
- チェックポイント復帰で HP と位置が戻り、**設置物が持ち越されない**こと
- **ステージ到達性監査** — 静的地形・移動床・崩落床を合わせて、すべての穴が
  歩きジャンプ（193px）／スプリント（226px）／空中ダッシュ（326px）／足場 1 枚（602px）
  のどれかで越えられるか。**この 4 つの数字は定数ではなく、同じ実行の中で
  実際にランナーを飛ばして測った値**なので、物理を触れば監査も一緒に動く
- **ガーディアン退屈監査** — 企画書 8 章の「神側が暇にならない」を数値化。
  ステージ全体で最長の無タスク区間が 10 秒を超えないこと（現状 **4.4 秒**）
- **タッチ配置監査** — 二人のボタンが 1 つも重ならないこと（5 種類のアスペクト比で）
- **敵の生存監査** — ランナーを遠くに置いたまま 12 秒回して、巡回敵が自分で
  足場から落ちて消えていないこと
- **素材監査** — 登録簿の全テクスチャとフォントが実在して読み込めること。
  欠けていると描画は黙ってベクターに戻るので、テストが唯一の検出手段

### Android ビルド

```bash
GODOT=/path/to/godot ANDROID_HOME=/path/to/android-sdk tools/build-android.sh
```

**APK は2本出る。** レンダラは project 設定なので、スクリプトが `project.godot` を
書き換えて2回書き出す。パッケージ ID が違うので**同じ端末に両方入れて比べられる**。

| ファイル | レンダラ | 性格 |
|---|---|---|
| `side-sky-vulkan.apk` | Vulkan（Godot の "mobile"） | 新しい端末で速い |
| `side-sky-gles3.apk` | GLES3（"compatibility"） | 対応端末が広い。純粋な2Dではこちらが速いことも多い |

実機で試せない環境で作っているため、レンダラを1つに賭けずに両方出している。

署名は `ci/debug.keystore`（**リポジトリにコミット済み・秘密ではない**）。
毎回同じ鍵で署名されるので端末に上書きインストールできる。ストア公開には使えない
——理由と本番鍵の作り方は [`ci/README.md`](ci/README.md) に。

### ダウンロード

ビルド済みの APK を [`dist/`](dist/) に置いてある（[説明](dist/README.md)）。
端末で直接開けばインストールできる。

CI（`.github/workflows/android.yml`）はブランチへの push、`v*` タグ、Actions タブからの
手動実行で走り、テストを通したうえで両 APK をビルドして **Release に添付**する。
ただし**現状このリポジトリでは Actions が起動しない**（run は作られるが数秒で
ログ無しに終了する＝Actions が利用できない状態。private リポジトリの請求設定が
よくある原因）。有効化すれば以後は Release が自動で出るので、そのとき `dist/` は消してよい。

### iOS ビルド

**Codemagic で行います。GitHub Actions ではありません。**
署名付き（TestFlight 向け）の手順は **[`docs/testflight.md`](docs/testflight.md)** に分けてあります。

このリポジトリでは Actions が動きません——run は生成されるのに、ランナーが割り当てられず
3秒で failure、ステップ0件、課金0ミリ秒、ログもチェックランの出力も空。
同じアカウントの **public リポジトリでは正常にビルドが通り**、無料枠も 2,000 分中
100 分しか使っていないので、これは private リポジトリ側の権限・課金の問題であって
ワークフローの問題ではありません。原因は GitHub の UI にも API にも出てきません。

Codemagic ならそこを迂回できます。**macOS ビルドが月 500 分無料**で、
**private リポジトリのまま**使えます（リポジトリを public にする必要はありません）。

```
1. codemagic.io に GitHub でサインイン、このリポジトリを認可
2. Add application → 555734/Kiki → codemagic.yaml が自動で見つかる
3. ブランチを選んで Start new build
4. .ipa と xcodebuild のログは、ビルドページから直接ダウンロードできる
```

メールで受け取りたい場合は `codemagic.yaml` の末尾のコメントに書式があります
（**空の `recipients: []` は Codemagic が弾く**ので、ブロックごと外してあります）。

ローカルの Mac がある場合は `tools/build-ios.sh` が同じ手順です。

**出てくるのは未署名の `.ipa`** です。CI に証明書を置きたくないので意図的にそうしています
（＝**このリポジトリに Apple 関連の情報は一切入っていません**）。実機には
[AltStore](https://altstore.io) か [Sideloadly](https://sideloadly.io) で、
**あなたの PC 上で、あなたの Apple ID で**再署名して入れます。無料 Apple ID なら7日、
Developer Program なら1年もちます。

#### 検証できたこと / できていないこと

**iOS のエクスポートは Linux でも最後まで走る**（`.ipa` へのパッケージングだけが macOS
限定で、`export_project_only=true` なのでそこは元々やらせていない）。なので
`tools/build-ios.sh` を `xcodebuild` の直前まで実際に通して確認した：

| | |
|---|---|
| プリセット名 `iOS` の解決 | **確認済み** |
| テンプレートの探索パスと `codemagic.yaml` の設置先の一致 | **確認済み**（`templates/ios.zip` の1件だけ） |
| Xcode プロジェクトが実際に生成されること | **確認済み**（`build/ios/xcode/side-sky.xcodeproj`） |
| スクリプトのプロジェクト検出 | **確認済み**（`find -maxdepth 2` の深さで一致） |
| 共有スキームの存在と名前 | **確認済み**（`side-sky.xcscheme`。`xcodebuild -list` で拾える） |
| `xcodebuild` が無い時に読める形で落ちること | **確認済み** |

**潰した不具合が2つ。どちらも実際に走らせなければ分からなかった：**

1. `Metal renderer require iOS 14+` — `min_ios_version` が 12.0 だった。このプロジェクトは
   mobile レンダラ（iOS では Metal）なので、Godot が組み合わせを拒否する
2. `App Store Team ID not specified` — 空だとエクスポート自体が通らない。
   ビルドは未署名なのでプレースホルダを入れてある（`DEVELOPMENT_TEAM` は
   `xcodebuild` 側で空にするので、値はバイナリに届かない）

**未検証：`xcodebuild` の実行そのものだけ**になった。ここは macOS が無いと分からない。
Godot が書くプロジェクトは**自動署名 (`CODE_SIGN_STYLE = Automatic`)** になっていて、
自動署名はアカウントとプロビジョニングプロファイルを探しに行くため、署名を切っていても
落ちうる。そこで `CODE_SIGN_STYLE=Manual` と `DEVELOPMENT_TEAM=""` を明示的に渡している
——これも**まだ実機で確かめていない**。

## 2人通信（EOS / Listen Server）

**最重要条件：開発者が常時稼働させるサーバーを 1 台も持たない。**
プレイヤーが 2 人でも 20 万人でも、こちらの月額は **¥0**。

| | |
|---|---|
| ホスト | **ランナー側の端末**（役割で決める。先に部屋を立てた方ではない） |
| 通信 | **EOS P2P**。NAT 越え失敗時は **EOS Relay（帯域無料）** |
| 部屋 | **EOS Lobby**（招待コード・オーナー移譲込み） |
| 認証 | **EOS Connect の Device ID**（匿名・Epic アカウント不要） |
| 自前サーバー | **0 台**（ゲーム / シグナリング / TURN / マッチメイキング すべて不要） |

ランナーがホストなので、**「画面では足場に乗ったのにホストでは落ちていた」は
ランナー側では原理的に起きない**。残るのは裏返し——ガーディアンの画面
（100〜200ms 過去）では間に合っていたのにホストではもう落ちていた——だけで、
そこはホスト側の**バックデート設置**で拾う。**巻き戻しはランナーを助ける方向にしか
転ばない**（不利になる再現結果は採用しない）ので、相手の回線でランナーが
理不尽に死ぬことがない。

帯域は 3 分類で設計している：

| | 例 | 量 |
|---|---|---|
| **毎フレーム（30Hz）** | ランナー位置・速度・状態、ゲージ | **13 B/tick（実測）= 0.4 KB/s** |
| **イベント時だけ** | 設置・狙撃・スイッチ・死亡・チェックポイント | 毎秒数回 |
| **送らない** | 移動床・レーザー・無傷の敵の巡回・演出・カメラ | **0 B**（tick の純関数） |

設計の全文は **[`docs/netcode.md`](docs/netcode.md)**。ホスト選定、authority の分割、
各対象の同期方式、Prediction / Interpolation / Reconciliation、パケットロス対策、
切断・再接続、チート対策と P2P の限界、コスト試算まで書いてある。

### あそびかた（オンライン）

離れた相手とテストプレイする手順は **[`docs/playtest.md`](docs/playtest.md)** にあります。

起動すると3通り出ます。

| | どうなるか | 必要なもの |
|---|---|---|
| **1台で2人であそぶ** | これまで通り。画面を左右で分け合う | なし |
| **同じWi-Fi** | ホスト側にIPが出る。相手がそれを入れる | 同じネットワーク |
| **インターネット** | ホストが**6文字の合言葉**を作る。相手がそれを入れる | 中継サーバー1つ（無料・後述） |

オンラインでは**各端末が自分の役割で画面を全部使います**（ランナーは左30%に押し込まれない）。

#### なぜインターネットには中継が要るのか

直接つなぐには、どちらかが**外から届くアドレス**を持っている必要があります。
普通の家庭のルーターの内側にいる2人は、どちらも持っていません。
そこで**両方が外へダイヤルする**——これはどのネットワークでも通ります。

中継は普通なら高くつく答えで、多くのゲームでは間違った選択です。
**このゲームでは成立します**——ランナーの端末がシミュレーションを持っているので、
ランナーの入力はそもそもネットワークを渡りません。増えた1ホップは**全部ガーディアン側に乗り**、
そのガーディアンは数秒先を読んでいて、コマンドは到着時にラグ補償されます。
両者がミリ秒の応答を必要とする設計では、この取引はできません。

#### 中継サーバーの立て方（無料・5分）

`server/signaling/` が Cloudflare Worker です。**無料枠に収まります**。

```bash
cd server/signaling
npm install
npx wrangler login          # Cloudflare の無料アカウント
npx wrangler deploy         # → https://side-sky.<あなた>.workers.dev が出る
```

出てきた URL をゲームの「中継サーバーのURL」に入れれば、以後は端末に記憶されます。
サーバーは**部屋の中身を一切読まず**、2人のあいだでバイト列をそのまま渡すだけです。

**正直な限界**：WebSocket は TCP なので、パケットが1つ落ちると後ろがつかえます
（＝本当の意味での「信頼性なしチャネル」が無い）。スナップショットは古いものを
受信側が捨てるので実害は小さいですが、EOS P2P には本物の不達許容チャネルがあり、
そちらが上位互換です。`NetTransport` の差し替えで入ります。
