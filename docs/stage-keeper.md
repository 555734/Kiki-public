# 1-B「THE KEEPER」設計

新ステージ。**このゲーム初のボス戦**で、`docs/status.md` 8 章が次の一手として
挙げていた「ボスと縦切り」のうちボスにあたる。

このステージに限ってゲームシステムを足している（4 章）。足したものは 3 つだけで、
**新しいボタンは 1 つも増えていない**。ランナーの操作もガーディアンの道具も、
1-1 で覚えたものがそのまま最後まで使われる。

---

## 1. なぜボスなのか

既存の 5 ステージは全部**移動**の話をしている。穴を越える、追われて逃げる、
見えない床を探す——形は違っても、問いは「どうやって前に進むか」ひとつ。

ボス戦は**前に進まない**。同じ場所に留まって、同じ相手と何度も向き合う。
そこで初めて聞ける問いがある：

> **二人は、同じ 1 秒に賭けられるか。**

1-C の盾持ち敵がその問いの縮小版だった（ランナーが振り向かせ、ガーディアンが
開いた背中を撃つ）。あれを 1 体 2 発で終わらせず、**6 回・3 幕**に引き伸ばして、
毎回少しずつ猶予を削っていくとどうなるか——それが 1-B。

### 企画書の死んだ一行を生かす

`balance.gd` にこう書いてある。

```gdscript
## [DOC] Wall: max 1 alive, 4 seconds. Blocks shots and charges.
const WALL_LIFETIME: float = 4.0
```

**"and charges"。** 企画書 4 章が壁に与えた 2 つ目の役目で、
**このゲームには今まで「チャージしてくる敵」が 1 体もいなかった。**
最初のコミットからずっと、この語は何も指していない。

THE KEEPER は突進する。だから壁が壁になる。新機能ではなく、
**すでに仕様として書かれていて実体がなかったものに実体を与える**のが
このステージの本体。

---

## 2. 戦いの形

アリーナ 1 つ。幅 1,450px、床は平ら、両端は閉じている。
右の門は番人が倒れるまで開かない。

### 一巡（サイクル）

```
   番人が歩いて寄る
        ↓
   ①  足を踏み、頭を下げる                  ← 予告 0.85 秒（幕が進むと短くなる）
        ↓
   ②  突進（760px/秒・最大 820px）
        ↓
   ③a ランナーの後ろにある何かにぶつかる
        → よろける（2.6 秒）→ 背中の炉心が開く
   ③b 何にもぶつからない → 地面を叩く → 衝撃波が左右に走る
        ↓
   ④  炉心に 1 発。当たった瞬間に閉じる（よろけ自体は最後まで続く）
```

ランナーがやることは 2 つしかない。

> **後ろに「何か」がある場所に立つ。そして突進を跳び越える。**

番人は**必ず突進してくる**。避けるかどうかではなく、**どこで受けるか**が
ランナーの判断になる。後ろに壁があれば番人は自分で自分を気絶させ、
何も無ければ突進は空振りして、地面を叩いて衝撃波が返ってくる。

### 跳び越えは「実測で」成立している

突進はスプリント（410px/秒）より速い 760px/秒。**逃げ切るという選択肢は無い。**
残るのは上——このゲームでランナーだけが持っていて番人が持っていないもの。

| | 実測 |
|---|---|
| 立ちジャンプの到達高 | **162px** |
| 足が番人の当たり判定（110px）より上にある時間 | **0.400 秒** |
| 番人がランナーを通過するのにかかる時間 | **0.197 秒** |

**猶予は約 2 倍。** フレーム単位の入力ではない。
この 2 つの数字は `test/keeper_probe.gd` が毎回**実際に跳ばせて**測っていて、
物理を触って猶予が 1.35 倍を切ればその場でテストが落ちる。

そして**跳べない／跳びたくない**ときの答えがもう 1 つある——
**ガーディアンの足場**。地上 110px より上に板を出せば、突進はその下を通る。

### 「ぶつかる」の中身

突進を止められるものは 2 つ。

| | 由来 | 挙動 |
|---|---|---|
| **石の防壁**（barricade） | ステージが置いている | 止まる → よろける。幕ごとに減る |
| **ガーディアンの壁** | 25 ゲージ・4 秒・1 枚 | 止まる → よろける。**壊れない** |

壁を壊さない理由：壁はすでに 25 ゲージと 4 秒を払っている。
**同じ 1 つの判断に税を二重取りしない**。壊れる演出は気持ちいいが、
それは「壁は突進を止める」という企画書の一行に条件を足すことになる。

## 3. 最初の設計は間違っていて、テストがそれを言った

最初、防壁は**床から空まで届く石柱**だった。ランナーは柱の裏に隠れ、
番人は「見えている相手にしか突進しない」というルールで、
姿を見せる → 予告 → 柱の裏に走る、という設計だった。

`test/keeper_probe.gd` を書いて走らせたら、こう落ちた。

```
FAIL  1: the runner reaches cover inside the wind-up  -- stopped at x=167
```

x=167 は柱の右面 + ランナーの半身。**ランナーは隠れるべき柱に正面衝突していた。**
横スクロールでは、**柱は遮蔽物ではなく仕切り**だった。ランナーは越えられず、
番人も越えられず、アリーナは永久に 3 分割されていた。

そこで 3 つ全部を作り直した。

| 変えたもの | 前 | 後 |
|---|---|---|
| 遮蔽物 | 石柱 250px（越えられない） | **防壁 128px**（跳び越えられる） |
| 番人の突進条件 | 見えているときだけ | **常に**（隠れるという行為が無くなった） |
| ランナーの回避 | 柱の裏に走る | **跳び越える／足場に乗る** |

**防壁は地形ではない。** 独自の当たり判定レイヤー
（`Balance.LAYER_BARRICADE`）に乗っていて、見ているのは 2 人だけ：

- **ランナー**（跳び越えられる／上に乗れる）
- **突進中の番人**（頭を下げた瞬間だけレイヤーをマスクに足す）

**歩いている番人は防壁をまたぐ。** 四つ脚の攻城機械が足を上げる、という絵で、
コードでは `_enter()` の 1 行。これが無いと番人は自分のアリーナの半分から
締め出され、ランナーには永久安全地帯ができる。

> 最初の版のルール（見えなければ突進しない）は、**実在した問題への間違った答え**
> だった。問題は「柱の裏に座っていれば勝てる」。答えは「跳び越えられる遮蔽物」で、
> それは同時に「隠れる」という行為そのものを消した。

## 4. このステージだけのルール（3 つ）

### ルール 1：突進が終わる場所は、**ランナーの後ろ**にあるものが決める

番人は常に突進する。だからランナーが選ぶのは**避けるかどうか**ではなく
**立つ場所**。後ろに防壁がある位置で受ければ番人は自滅し、
無ければ突進は空振りして衝撃波が返る。

「後ろに何かあるか」はゲーム内にも出ている——予告中、番人の足元から
**突進の軌道が床に描かれる**（`KEEPER_CHARGE_DISTANCE` そのもので描くので、
線の先に立っている人は本当に安全）。二人ともこれを見ている。

### ルール 2：炉心は**よろけている間だけ**開き、**当たれば閉じる**

`Keeper.exposed()` が

```
state == STAGGER  かつ  まだこのよろけで被弾していない
```

を返し、`Core.take_damage` が閉じてから親に 1 傷を渡す。
ライフルのアシスト（110px）が閉じた炉心に吸い寄せられないよう、
`is_shootable_now()` も同じ答えを返す（盾持ち敵と同じ約束）。

**被弾してもよろけは短くならない。** 撃たれたことが立ち直りの助けになるのは
おかしいし、実務的にはこちらのほうが重要で——最初の実装は被弾で
よろけを打ち切っていたので、`wounded_this_stagger` は**飾り**だった。
負のコントロール（フラグを消す）を掛けたらテストが**通ってしまった**ので、
よろけを最後まで走らせて、フラグに本当の仕事をさせた。

### ルール 3：幕が変わると番人が**防壁を壊す**

| 幕 | 傷 | 防壁 | 予告 | よろけ | 衝撃波 |
|---|---|---|---|---|---|
| 一幕 | 6 → 4 | **2 枚** | 0.85 秒 | 2.6 秒 | なし |
| 二幕 | 4 → 2 | **1 枚** | 0.70 秒 | 2.2 秒 | あり |
| 三幕 | 2 → 0 | **0 枚** | 0.55 秒 | 1.8 秒 | あり・速い |

防壁は「ガーディアンの壁の練習台」。ステージが 2 回ぶんタダで貸してくれて、
そのあと取り上げる。**三幕で壁を置けるかどうかは、一幕で防壁がやっていたことを
見ていたかどうかで決まる。**

防壁が減るのは幕の切り替わりであって、突進の当たりどころではない。
理由は 8 章（リスポーンと決定性）。

## 5. 三つの道具が、三つとも別の意味になる

このステージの一番うれしいところ。**能力は 1 つも増えていないのに、
3 つの道具の意味が全部変わる。**

| 道具 | 平常時の意味 | 1-B での意味 |
|---|---|---|
| **壁** (25) | 弾を遮る盾 | **防壁の代わり。突進を止め、よろけを作る**（＝三幕で唯一の攻め手） |
| **足場** (30) | 届かない場所への床 | **突進と衝撃波の上に立つ避難台**。跳ばずに避ける |
| **狙撃** (20) | 敵を消す | **開いた炉心への 1 発**。他に当てても意味がない |

### ゲージの収支

| | |
|---|---|
| 1 サイクルの長さ | 約 5 秒 |
| その間に回復するゲージ | 8/秒 × 5 = **40** |
| 壁 + 狙撃 | 25 + 20 = **45** |
| 足場 + 狙撃 | 30 + 20 = **50** |

**1 サイクルの収入では「守りの道具 1 つ + 1 発」がぎりぎり買えない。**
だから貯める判断が要るし、拾いに行く理由ができる。

アリーナには結晶が 3 つ置いてある（1 つ 34 ゲージ）。
どれも**アリーナの床の上**——つまり突進路の上にあり、拾いに行くのは危ない。
「今なら取れる」を言うのはガーディアンの仕事になる。

## 6. ランナーは何をしているのか

ボス戦で一番ありがちな失敗は、**ランナーが観客になること**。
撃つのはガーディアンなので、放っておくとそうなる。

このステージでランナーがやっていること：

1. **受ける場所を選ぶ**。後ろに防壁（三幕では壁）がある位置に立つ
2. **突進を跳び越える**。0.4 秒の猶予を 0.197 秒の通過に合わせる
3. **衝撃波を飛ぶ**（二幕以降）
4. **結晶を取りに行く**。ガーディアンの弾薬はランナーの足で増える
5. **防壁に登って**突進をやり過ごす（上に乗れる）

ランナーは番人に 1 ダメージも与えられない。与えられないまま、
**6 回の傷は全部ランナーが作っている**。

ランナーの HP は 2。接触は 1 ハート + 強めのノックバック。
**穴は 1 つも無い**ので、死因は接触と衝撃波だけ。

## 7. 番人そのもの

| | |
|---|---|
| 当たり判定 | 120 x 110px |
| 描画 | 168 x 134px（**わざと大きい**） |
| 歩き | 95px/秒（ランナーの歩き 274px/秒） |
| 突進 | 760px/秒（ランナーのスプリント 410px/秒） |
| 傷 | 6（炉心 1 発 = 1 傷） |

**当たり判定より絵が大きい。** 攻城獣として読めるシルエットは横に長く、
横に長いものは通過に時間がかかり、通過に時間がかかると跳び越えが
フレーム単位の入力になる。なので**痛いのは頭と肩だけ**にして、
脚は絵として張り出している。

## 8. リスポーンと決定性

死んだら**幕の頭に戻る**。傷は最大 2 つぶんしか巻き戻らない。

```
二幕の途中（傷 3）で死ぬ → 傷 4 の状態（二幕の頭）から再開
```

全快させない理由：ボスが全快するゲームは、6 サイクル目のミスが
**6 サイクル全部を捨てさせる**。このゲームは死亡から短時間で戻す設計
（`docs/status.md` 3 章）で、その思想と全快は両立しない。

防壁を「突進の当たりどころで壊す」のではなく「幕で壊す」のはこのため。
リスポーンは `rebuild_dynamic()` で全部作り直すので、
**防壁の枚数が幕の関数**でないと、死ぬたびに防壁が復活して三幕が三幕でなくなる。

```gdscript
static func barricades_for_act(which_act: int) -> int:
    return maxi(0, 3 - clampi(which_act, 1, 3))   # 幕1→2枚, 幕2→1枚, 幕3→0枚
```

同じ理由で、番人の傷は `GameState.boss_hp` に持たせてある
（結晶の `crystals_taken` と同じ扱い。ノードは作り直されるが、進行は残る）。

値は 3 通りある。

| | |
|---|---|
| `-1` | まだ戦っていない |
| 正の数 | 残りの傷 |
| `0` | **もう倒した** |

最後の 1 つが要る理由：**倒したあとに死ぬことがある**。番人が崩れる 1.6 秒のあいだ、
最後に放った衝撃波はまだ走っている。そこでランナーが 2 発もらうと、リスポーンが
`rebuild_dynamic()` を呼び、番人が**満タンで生き返って門も閉じ直す**。
なので `0` のときは `LevelBuilder` が番人を作らず、門だけ開けて建てる。

（これはテストが見つけたのではなく、コードを読み返して見つけた。
見つけたあとチェックを書き、**ガードを外して落ちることを確認**してある。）

## 9. 通信

**1 通だけ増やした。** `Protocol.Msg.BOSS`（10 バイト）。

```
net_id(u16) state(u8) hp(u8) timer(u16, ms) facing(i8) spent(u8)
```

送るのは**状態が変わった瞬間**と、0.5 秒ごとの保険。1 サイクルに 5〜6 通。

なぜ必要か——ガーディアンの端末では敵の `_physics_process` が切ってある
（スナップショットで動く人形）ので、番人の状態機械は**回らない**。
つまり神の端末は、放っておくと

- いつ炉心が開いたか分からない
- 突進中なのかよろけ中なのか分からない

という、**撃つ側が一番知らないといけないことを 2 つとも知らない**状態になる。
これは 1-C の盾持ち敵で実際に踏んだ穴（`docs/status.md` 6 章「神側から盾持ち敵が
倒せない」）と同じ形なので、最初から状態を送る。

送らないもの：

| | 理由 |
|---|---|
| 番人の座標 | 既存の `dirty_enemies` に乗る（敵 1 体 +6 バイト） |
| 衝撃波 | 状態 SLAM が届いた時点で**両端末が自分で生成**する。当たり判定はホストだけ |
| 防壁 | ステージデータと `GameState.boss_hp` の関数。0 バイト |
| 炉心の開閉 | `state` と `spent` から導ける。`WEAK_WINDOW` は使わない |

`Protocol.VERSION` は 10 → 11。ビルドが違う二人は握手で弾かれる。

## 10. 何を測っているか

`test/keeper_probe.gd`、**65 チェック**。他の probe と同じく、実際に戦わせる。

数字はモデルではなく実測を使う（1-C で「射出の飛距離を重力の式で出したら
2 倍ずれていた」をやっているので）。

| 何を | なぜ |
|---|---|
| 突進速度 > スプリント速度 | 「逃げ切れない」が設計の前提 |
| **跳躍の猶予 > 通過時間 × 1.35** | 回避がフレーム単位でないこと（**両方とも実測**） |
| 防壁 > 番人の当たり判定 | 突進が乗り越えないこと |
| **防壁 < ジャンプ到達高** | **遮蔽物であって仕切りでないこと**（3 章で落ちたやつ） |
| 防壁が地形レイヤーに乗っていない | 歩く番人が締め出されないこと |
| ランナーが防壁に登れて、降りられる | 同上、実際にやらせる |
| 突進が防壁で止まり、炉心が開く | サイクルの中核 |
| **壁でも同じことが起きる** | 企画書の "and charges" |
| 炉心は 1 発で閉じる | ルール 2 |
| 閉じた炉心はアシストが拾わない | 盾持ち敵で潰したのと同じ穴 |
| 閉じた炉心への射撃は「拒否」と言う | 外したのと区別がつくこと |
| 6 発で倒れて門が開く | 通しで終われるか |
| 幕ごとに防壁が減る | ルール 3 |
| 死んでも幕の頭までしか戻らない | 8 章 |
| **倒したあとに建て直しても生き返らない**／門は開いたまま | 8 章の 3 値 |
| 衝撃波は足場の上に届かない | 足場の新しい意味 |
| 門の上に梁がある | 足場でボスを迂回できないこと |
| 使う絵が全部登録簿にある | 素材監査（11 章） |

### 負のコントロール（3 本、実施済み）

新しいチェックを入れたら、守っているものを壊して落ちることを確認する。

| 壊したもの | 結果 |
|---|---|
| 突進マスクからホログラム層を外す | **5 チェックが落ちた**（壁が突進を止めなくなる） |
| 防壁を地形レイヤーに戻す | **2 チェックが落ちた** |
| `wounded_this_stagger` を無視する | **最初は落ちなかった** → 4 章ルール 2 のとおり実装を直し、落ちるようになった |
| 「もう倒した」のガードを外す | **2 チェックが落ちた**（番人が満タンで生き返る） |

3 本目がこの手順の価値そのもので、**テストではなく実装のほうが間違っていた**。

`test/keeper_probe.gd` は現在 **65 チェック**。

## 11. 絵は後から来た

**このステージは絵が 1 枚も無い状態で設計し、測り、出した。**
寸法も読みやすさも全部ベクター描画のほうで決めてある——
`Art.tex()` が `null` を返したら手描きに落ちる、というのは
このリポジトリが最初から持っている仕組み（`src/render/art.gd`）。

その 13 枚が届いて、いま `assets/keeper/` に入っている。
**ゲームコードは 1 行も変わっていない**（描き方の直しが 1 件だけあり、
それは 1-S 側の話——`assets/SOURCES.md`）。

### 待っているあいだ、監査をどう生かしておいたか

素材監査（「登録簿の全テクスチャが実在するか」）は 13 枚ぶん赤くなるので、
`Art.PENDING` という**例外リスト**を足した。そして例外そのものを監査している：

- `pending_unknown()` — PENDING に登録簿に無いキーがあれば落ちる（打ち間違い）
- `pending_but_present()` — **ファイルが届いたキーが PENDING に残っていたら落ちる**

2 つ目が要点で、これが無いと「例外にしたまま出荷されて、監査が永久に効かない絵」が
生まれる。実際、絵が届いたときにやったのは PENDING から 13 行消すことだけで、
**消し忘れればテストが落ちる**。いま `PENDING` は空。

### フォールバックが 1 つ、もう効かなくなった

`Art._prefer(["keeper_panorama", "horror_panorama"])` のような連鎖で、
1-B は絵が届くまで 1-2 の夜の素材を借りていた（キノコの城のある真昼の 1-1 に

### 4 つのポーズは 1 枚のキャンバスに載せ直してある

渡された 4 枚は、床の高さが **45 / 96 / 149 / 62px** とばらばらだった。
そのまま 1 枚ずつ縮めると、**構える／突進する／よろめくたびに番人の背が変わる**。
ランナーの 8 ポーズと同じ処理（1 つの倍率・1 つのキャンバス・足元合わせ）を
`tools/import_assets.py --stage-art` に足して通してある。
