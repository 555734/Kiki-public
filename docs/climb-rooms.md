# 1-7 / 1-8 の部屋構成

1-7(時計塔)と1-8(地下洞窟)は、以前は同じ形の「4段の小部屋」を20回以上繰り返していた。
今は1部屋ずつ別のアイデアで作った部屋を積み上げている。1-7が20部屋、1-8が22部屋で、同じ部屋は2度出てこない。

## 作り方

- `src/levels/section_builder.gd`(SectionBuilder)
  - 部屋は「入ってきた足場」を原点にした相対座標で書く。`at(dx, dy)` の dx は部屋の向き、dy は上方向。
  - 同じ部屋を左右どちら向きにも置ける。どちら向きにするかは `best_turn` が決める。
  - `best_turn` は、縦穴からはみ出さず、下の部屋とぶつからず、出口が中央寄りになる向きを選ぶ。次の1部屋分も先読みする。
- 各部屋は「想定ルート」を記録する。種類は次のとおり。
  - `jump`(通常ジャンプ)
  - `double`(2段ジャンプ)
  - `assist`(ガーディアンの足場で登る)
  - `ride`(バネ、矢印パッド、ワープ、上昇気流、時間で動く仕掛け、扉、隠し橋)
- 部屋どうしの干渉チェックは、次の箱を使う。
  - 動く仕掛けが動く範囲全体。
  - 固い地形。
  - 想定ルートのジャンプが通る空間。
- `test/climb_probe.tscn` は、本物のランナー・本物の仕掛け・本物のガーディアン足場で、想定ルートの全手順(1-7は70手、1-8は69手)を実際に登る。時計で動く仕掛けは、時計の位相を変えて何度か試す。
- 敵の一部(機雷、コウモリ、甲虫)は `Wander` で不規則に飛び回る。動きはステージ時計の純粋な関数なので、ホストとゲストで同じ動きになり、通信量は増えない。

## 途中で見つかったゲーム側の不具合

上昇気流の中でジャンプボタンを離すと、ランナーが空中で止まったままになっていた。

- 原因:ジャンプを離したときの強い重力は、速度をゼロで止める仕様になっている。気流が上に押し、離した重力がそれを打ち消す、という状態が毎フレーム続いていた。
- 修正:今は、気流に入るとジャンプの操作がそこで終わる。バネや矢印パッドと同じ扱い。
- 回帰テスト:`movement_tests._test_updraft_after_tapped_jump`。
