# 対戦修正（2026-09-21）

対象: `recovery/unified`、修正前 `b1cd2f3`。

## 変更

- 参加側の復活直後に、遅れて返ってきた本人の `alive=false` を死亡命令として再適用していた処理を削除。現行の「自分のRunnerは自分で動かす」方式に合わせ、復活を繰り返して操作不能になる状態を修正した。
- ホストは参加側の生存→死亡の変化を一度だけ処理し、所持コインを返却する。同じ死亡中の観測を受け続けても返却・状態初期化を繰り返さない。
- 対戦コースは1-1のA〜Dを使い、周回長を19,000pxから13,000pxへ短縮。終端は35px刻みの階段で始点の高さへつなぐ。協力プレイの1-1は変更していない。
- コインは安全な候補地点をホストの乱数で抽選し、地点内にも最大24pxの横方向のばらつきを付ける。直前の出現地点と既にコインがある場所を避け、壁内部や足場のない場所には生成しない。
- 対戦画面に混ざっていた本編の固定配置ゲージ用コインを除去。対戦用のコイン台帳・10枚先取・18枚の総数・3枚を目安にする補充は維持。
- 通信バージョンを4へ更新。旧マップの端末と混在して遊ぶことを防ぐため、**両端末とも新しいビルドへ更新が必要**。

## 検証

`versus_touch_probe` で2つの独立した対戦sceneを接続し、画面にタッチイベントを送る。各側で死亡を2回起こし、所持返却・復活・無敵点滅の終了・復活後の移動を確認する。修正前は参加側の8項目が失敗し、修正後は通過。50ms RTTと200ms RTTの両方で通過した。

`versus_probe` は乱数seedの再現性、異なるseedで位置が変わること、全4区間への分布、生成位置の安全性、台帳保存と短縮コースの周回を確認。`versus_play_probe` は実Runnerの歩行・被弾・取得・復帰・両方向の周回、`versus_net_probe` は4役の状態一致を検証する。

これらはGodot headlessでの自動検証。実スマートフォン2台での操作・回線品質の確認を代替するものではない。既存の通信方式を全面置換したり、移動・ジャンプの数値を変更したりはしていない。
